# Validation and evidence

Automated checks and native-host acceptance are different evidence. A unit/browser harness cannot establish Power BI Desktop import, tenant behavior, export compatibility, assistive-technology usability, or Microsoft certification.

## Repeatable local checks

Prerequisites: Node.js 24.17, npm 11, and PowerShell 7 on Windows; OpenSSL is required for non-Windows packaging. From the repository root:

```powershell
npm ci
npm run typecheck
npm run lint
npm run test
npm run notices
npm run package
npm run test:browser
npm run audit:package
npm run sample
node .\samples\prepare-transitions.mjs --check --self-test
node .\samples\check-report-source.mjs
node .\scripts\generate-icons.mjs --check
```

Run only in an authorized development environment. Package installation and browser installation are development activities, not visual-runtime network use. Consult package scripts/configuration for browser prerequisites.

If the browser runner reports a missing Chromium executable, use `npm run browser:install`. The browser wrapper keeps both installation and execution scoped to `.tmp/browsers` in this worktree. Browser tests load the JavaScript and CSS extracted from the actual `.pbiviz`, intercept runtime network requests, and use a simulated Power BI host; they do not test a separately bundled source demo.

An already installed Chromium-based Microsoft Edge is also supported without downloading a browser: `$env:PROCESS_LENS_BROWSER_CHANNEL = 'msedge'; npm run test:browser`. Record the chosen browser/channel with the result. This remains a browser harness, not native Power BI.

The package commands invoke official tooling through `scripts/package.mjs`, using an ephemeral development certificate generated by .NET `CertificateRequest` on Windows or OpenSSL elsewhere. The wrapper scopes `HOME`/`USERPROFILE` to ignored `.tmp/package-home-*` and removes its invocation directory afterward. It does not write certificate stores or change trust settings, and no development server is required.

Run `npm run audit:certification` for the official tooling's certification-audit option through that same wrapper. Record its real result; it is not a Microsoft certification decision. Also run `npm audit` and `npm audit --omit=dev`, retaining full and production-only dependency-audit evidence for the actual release lockfile.

`npm run notices` generates root `THIRD-PARTY-NOTICES.txt` and `src/notices.ts`. The latter is bundled by the official packager and available in the visual's offline legal disclosure, so recipients of the `.pbiviz` receive the required upstream license text even without a webpack license sidecar. The packaged-browser test compares the disclosure with the generated full text. Package audit also copies the sidecar into ignored `dist`. Packaging outputs, audit metadata, and checksums belong in `dist`; retain release evidence outside source as appropriate.

## Tooling decisions

The package wrapper uses supported `--all-locales --no-stats` flags because tools 7.2.1's locale-pruning loader fails on formattingutils 7's ESM locale module. Numeric/date locale resources remain fully offline; this does not add UI translations beyond English/French. No dependency implementation is patched.

The official feature scanner still warns about **Highlight Data** (intentionally disabled for the table contract) and **Localizations** (it searches for `.createLocalizationManager`; this visual uses host-locale-selected UI dictionaries and packaged field-role resources). These warnings are not a certification result. Actual UI, role localization, and numeric formatting must still be verified in native hosts.

The lockfile pins Vitest 4.1.11 and uses patched `qs` 6.16.0 and a scoped `sockjs`/`uuid` 11.1.1 override to avoid known development-tree advisories. SockJS uses the unchanged `require("uuid").v4()` API. Neither the SDK development server nor these server dependencies is part of the shipped runtime. Reassess overrides when upgrading the SDK.

The sample check verifies fixture totals, every prepared row's adjacent-event mean/frequency, tie/sequence handling, calendar dates, duplicate IDs/sequences, variant-path consistency, invalid IDs, CSV syntax, and deterministic record ordering. The report check only verifies JSON syntax, references, expected fields, and the intended local CSV partition. It does not parse TMDL with the Analysis Services engine or validate PBIR against live Microsoft schemas.

## Required native Desktop checks — unverified

Record tester, date, Desktop version, OS, package hash, dataset, steps, actual result, and any defects. Do not mark pass from a mocked host.

The accepted interaction contract is host cross-filtering plus local selected-row highlighting with `supportsHighlight: false`; incoming categorical highlight measures are not part of acceptance.

1. **Real import and binding:** import the packaged `.pbiviz`; check identity/version, all field roles, no field-well surprises, format-pane cards, save/reopen, and resize. Confirm the source PBIP opens, `CsvPath` changes, CSV refreshes, and native table values match.
2. **Semantics:** confirm 24 total accepted sample transitions and the documented per-variant values. Preserve `Triage → Triage` and `Triage ↔ Waiting`. Cross-variant/duplicate duration is unavailable, never a combined mean. Removing metric provenance/statistic/unit must not imply a guessed definition.
3. **Grain:** compare native table vs visual with/without `rowKey`, with duplicate prepared rows, and with guarded vs unsafe implicit duration measures. Verify the limitation that upstream coalescing is not observable by the visual.
4. **Cross-filtering and identity:** select a transition, activity, and variant row group; every represented host row identity participates. Test report interaction settings, multiple selection, clear selection, drill/context menus, native tooltip values, and missing identity. Confirm local filtering alone does not unexpectedly cross-filter the report.
5. **Incoming interactions:** use native slicers/visuals to cross-filter the custom visual. Do not expect incoming categorical highlight measures from a table mapping. Check selected-state highlighting locally.
6. **Data and bounds:** empty fields/view, missing required roles, invalid/blank/long IDs, invalid frequencies/durations, numeric overflow, zero values, host segmentation, >2,000 received rows, >80 activities, >300 variant edges, and changes in filtered data. Confirm visible subset diagnostics and no additional data-window fetching.
7. **Formatting:** node/edge colors, edge labels, duration statistic/unit/provenance, reset to defaults, persistence, and locale formatting.
8. **Accessibility:** keyboard-only navigation through controls, list/table and row actions, Enter/Space, context-menu key/Shift+F10, visible focus, focus restoration after filtering, tooltip discoverability, and multi-select behavior where offered. Test native host screen readers, accessible names/state, reading order, high contrast, zoom, small containers, and not relying on color alone.
9. **Locale and direction:** English, French, an unsupported locale with English fallback, and Arabic/Hebrew host locales for RTL. Check mixed-direction IDs, truncation, large numbers, and units. Confirm reduced-motion preference causes no animation.
10. **Data handling:** inspect the packaged runtime for external calls/remote assets/telemetry, check an authorized native-host network trace if available, and distinguish host traffic from visual-initiated traffic. Empty privileges alone is not a complete privacy or security review.

## Required Service and export checks — unverified

- Publish only to an authorized tenant/workspace; record tenant custom-visual policies and permissions. Verify real import, refresh/data-source behavior, report save/open, selection, filtering, tooltips, formatting, and accessibility in supported browsers.
- Local `File.Contents` refresh needs an explicitly configured deployment/refresh solution; the example does not provide a Service gateway or cloud data source.
- Test PDF, PowerPoint, image/export paths and subscriptions relevant to the intended distribution. Check whether the tenant allows each feature for this non-certified custom visual. A feature unavailable due to policy must be recorded as such, not as a successful export.
- Compare exported visible metrics and warnings with the interactive report. Export behavior is **not guaranteed** by the SVG layout or automated browser tests.
- Test report updates with the frozen GUID and versioned artifact. Capture actual host behavior and any migration issues; do not imply Microsoft certification.
